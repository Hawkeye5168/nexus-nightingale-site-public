What this check is

Each dossier was treated as a set of separate claims, not one pass/fail document. On 7 November 2026 we checked:

Identity and sequence

UniProt accession, approved gene symbol and protein sequence length.

Disease code

Orphanet ORPHA code and preferred disease name, opened in a browser.

Trial landscape

Current ClinicalTrials.gov total for the named condition, with the retrieval date.

Literature and structure

Key PubMed citation resolved; named PDB entries resolved to their actual construct titles.

What changed as a result

  • “Verified” was replaced by “Source-linked research registry” across the public pages.
  • Trial totals were refreshed against ClinicalTrials.gov; stale totals were corrected.
  • FXN now names 3T3K, 1EKG and 3S4M separately instead of implying one structure is another.
  • A wrong OMIM cross-reference for neonatal diabetes was corrected from 606176 (GCK / PNDM1) to 618856 (KCNJ11 / PNDM2).
  • Each page carries a dated Source check 7 Nov 2026 note.
  • Public data records were scrubbed of the old “VERIFIED” wording while genuine UNVERIFIED flags remain.

What this does not establish

This is not clinical validation. It does not establish prevalence, natural history, efficacy, safety, regulatory approval or patient benefit. Prevalence text remains explicitly unverified. OMIM identifiers were checked against OMIM and ClinVar cross-references; one wrong neonatal ID was found and corrected. Full OMIM entry text was not re-read. Drug approval dates were not all re-fetched from regulators.

Orphanet confirmed the ORPHA code and page, not every statement on the page. A resolved citation is a citation, not proof that the claim is true.

Why publish this?

Because a dossier that hides its weak points is less useful than one that marks them. This is one public example of the standard we apply: identity, disease code, trial landscape, key citation and structure provenance checked on a stated date, with the remaining uncertainty left visible.
