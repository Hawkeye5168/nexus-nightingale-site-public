NEXUS NIGHTINGALE · Model assurance

A model is not evidence until it survives its control.

Assurance packs for biomarker classifiers and diagnostic rules: what the model detects, at an acceptable false-positive budget, on data it did not train on — and what it still does not establish.

This is the companion to a NEXUS dossier. The dossier answers what should happen next in this disease or target. The assurance pack answers does this model actually work well enough to be used. Same evidence discipline, different question.

What a pack gives you

Held-out performance

Subject-, patient-, site- or capture-level separation. Not a random row split that leaks the same patient into both sides.

Fixed operating points

Detection at explicit false-positive rates, with the counts behind each number. AUC is shown for contrast, never as the claim.

Per-category errors

One class is allowed to dominate the aggregate only if the table shows it. You see where the false alarms actually come from.

A null control

Permuted labels or a known-identity input, run through the identical pipeline. The result must collapse to the alarm budget.

Leakage checks

Duplicate rows, train/test overlap, identifiers used as features, and the dataset's documented traps.

A decision, not a dashboard

Deploy, iterate or stop — with the evidence that would change the answer and the limits stated plainly.

What it is not

Not a clinical or regulatory validation. A pack is a methods and performance document. It does not diagnose, recommend treatment, establish patient benefit or replace a prospective clinical study, a regulatory submission or an independent clinical reviewer. No patient identifiers are published.

The pack can recommend not deploying the model. A negative result is a valid, useful deliverable. A pack that can only say yes is not an assurance pack.

Two controls: one passes, one fails

A service that can only say no is not credible either. The same pack has to report a pass when the model earns one, and a rejection when it does not.

Positive control · MIT-001 · record-held-out

A model that passes at a 5% budget: 94.1% detection at 4.18% actual FPR.

MIT-001 is a real run on the public MIT-BIH Arrhythmia Database, split by record/patient group. The database has 48 records from 47 subjects; 201/202 are grouped, and record 232 has no N/V beats, so the control uses 47 records and 46 groups. The gain over the earlier sample-level control is that held-out records never enter training. The limit is that the 1% target is not met: the 1% calibration threshold gives 4.18% actual FPR, inside the declared 5% budget. A single global threshold gives 18.4% actual FPR, which is why the control uses a per-record normal baseline.

Negative control · AX-001 · subject-held-out

A model that fails: 11% detection at a 1% false-positive budget.

AX-001 is a real run on the public EEG seizure dataset. The signal is real but modest, and the pack recommends against deployment. It is the control that shows the pack can reject a model rather than dress it up.

How a client pack is built

StepWhat happens
1. QuestionOne intended use and one decision. The false-positive budget is agreed before the run.
2. DataClient data stays in the client environment unless a written handling agreement says otherwise. Source, checksum and split unit are recorded.
3. EvaluationHeld-out unit respected; fixed-FPR table; per-category table; null control; leakage checks.
4. PackA client-facing PDF/HTML with the decision, numbers, controls, limits and source register. No dashboard, no code licence.

The deliverable is the pack. It is not a model handover, a software licence, a clinical service or a regulatory submission.

Who it is for

Diagnostic and biomarker teams with a locked dataset and a classifier, risk score or rule that is being considered for a pilot. The same buyer as a NEXUS dossier, one stage later: the dossier decides the target; the assurance pack tests the instrument.

Research use only. No patient data, clinical advice, diagnosis, treatment recommendation, regulatory approval or claim of patient benefit is provided. A clinical claim needs a named clinical reviewer and the appropriate regulatory pathway.
